# F2 — integrate and verify the foundation

Owner: Vincent / separate A integration agent. Coordinator remains outside application code. State: Blocked until F1B, F1A and F1C have reviewed results, actual SHAs and stopped writers. Timebox: about 30 minutes. Branch: `codex/f2-foundation`.

At dispatch record the current integration base, all three lane result SHAs, `curb-v0` and the integration method. The orchestrator owns the merge decision and designates one publisher. Integrate B → A → C sequentially and record the resulting candidate SHA.

Allowed new edits: `tests/integration/foundation/`, `tests/e2e/` and exact verification/config files explicitly transferred by coordinator. Integration of reviewed lane commits is a Git action, not permission to rewrite other lanes. Nontrivial conflicts or behavioral fixes go back to the owning lane in a bounded correction task after confirming no active writer. A root config fix needs a serial A maintenance scope.

1. Inspect scope, diff and actual evidence for each lane. Confirm all children stopped. Preserve unrelated work.
2. Integrate authorized commits in order without changing any running worker checkout. Recheck affected behavior after conflict resolution or base movement.
3. Run `npm run check` on the final candidate; record command, result, timestamp and exact tested SHA. Add only useful full-flow verification, not tests that merely mirror implementation.
4. Exercise the [F2 browser checkpoint](../ACCEPTANCE.md): real API → select barrier → evidence → reset; loading/empty/error; keyboard and long-note behavior. Remove any temporary direct-fixture screen path through an owner-scoped correction.
5. Post RESULT with candidate SHA, lane SHAs, actual checks, walkthrough, known limits and rollback checkpoint. The orchestrator reviews the evidence and merges the accepted candidate or directs the designated integration owner to merge. Verify the resulting `origin/main` SHA and record it on the board. The browser checkpoint and required checks establish foundation acceptance.
6. **Stop new feature dispatch.** Show Vincent the foundation and propose route impact, evidence capture, or workflow revision as the next choice. Recommend route impact unless the observed workflow needs correction; await Vincent's direction before R1–R5.

Cut/rollback: preserve known-good F0 and lane branches, isolate the broken lane and assign the smallest repair. Do not expand to sponsor/runtime work to compensate for an integration failure.
