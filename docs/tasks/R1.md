## Visible outcome

Choose an origin and named destination, inspect the baseline route or a useful explanation of blocked/unknown/disconnected conditions, select at most one hypothetical repair, and compare before/after. Inspect the associated barrier evidence. Reset returns a known example and cancels stale work.

The planning profile is an authored step-free demo assumption, not measured accessibility or navigation advice. Rejected evidence does not prove a path passable, and no listed barrier does not imply verified passability. Unknown edges remain excluded after a repair. Observed/evidence records remain immutable.

## Acceptance

- A default trip is blocked before the selected repair and reachable afterward, with correct named nodes/edges and length. An already-reachable trip remains honest; no manufactured restored count.
- Directed edges, disconnected nodes, unknown coverage, same-node zero-length trips, deterministic ties and invalid IDs/revisions are covered.
- Clearing only one of two blockers on an edge cannot make it passable. Unknowns never become passable merely by clearing a barrier.
- Failure explanations distinguish structural disconnection from unknown-needed/blocked connections. Any explanatory edge list refers to a possible connection, not a unique explanation of all alternatives.
- Only the latest request may render; changing selections hides obsolete results, reset clears simulation, errors allow retry, and pending work is cancellable/bounded.
- Context/evaluation use the real local API. Before/after results and evidence match the selected tuple. No direct fixture fallback.
- Existing 53 foundation tests and original `/curb` behavior remain intact. Browser evidence includes keyboard operation and 390px width.
