# Campus Explorer archive features

Design proposal for CAMPUS-POINT-UI-PLAN/1. The Explorer baseline is `7546599a479cabc167168d21a7fc7ad6e25ac200` from PR #13. The retained point source is `e80f34b8fa3d0d2ba04a2954f97e94c4c06b0dd2`, schema `curb-campus-point-source` v1. Implementation needs a reviewed catalog and its own assignment. [UI planning assignment](https://github.com/oliverchennn/Curb/issues/1#issuecomment-6888737646) · [Catalog assignment](https://github.com/oliverchennn/Curb/issues/1#issuecomment-6888734042)

## Layout

| Option | Desktop at 1366 and 1920 px | At 390 px |
| --- | --- | --- |
| Map first | An optional archive-feature layer with a short legend and visible count. Select individual symbols at close zoom. Open a compact rail for details or search. | Keep the full-width map. Put the layer control and a feature-list button above it. |
| Inventory first | A searchable rail contains every record. The map shows just the selected eligible location. This is easy to browse with a keyboard and has little map clutter, but finding nearby features requires extra list interactions. | Use the same inventory as an inline section with an explicit **Show on map** action. |

Use the map-first layout with the inventory-first selection flow. Put one **Show archive features** toggle beside the Campus section controls, below them if the row wraps. The layer starts off. Preserve the four existing evidence groups, all legacy links and the default 1,188-way, 22-section campus overview. With the layer on, offer **Browse features**, a result count and a short four-symbol legend next to the map controls. Keep the existing Archive filter, campus picker, zoom, fit and background controls. The feature filter is a separate disclosure inside the feature browser. On desktop the browser uses the existing evidence-rail slot. Offer access to the selected way's details from that slot when a point is open. On mobile, put the browser in the document flow below the map and make **Browse features** open it and focus its heading or search field. Give the toggle, picker and list controls 44 px targets and let rows wrap within the document client width, including with a classic scrollbar.

## Inventory, map and evidence

- The inventory starts campus-wide in either campus view. It includes **333 unique OSM nodes, 329 eligible source positions and four entries pending location review**. Provide independent text search and exact `node/<id>` lookup. Search node ID, available source name and categories. Keep source order by numeric node ID for stable pagination. Provide four category choices with OR matching within the category filter. Add a single scope selector with **All features**, **Linked to this section** when applicable, **Perimeter context**, **No selected-way link** and **Location review needed**. Scope and text narrow the category results. An explicit section restriction uses exact memberships. Panning, zooming and changing sections leave the default inventory campus-wide.
- Show category membership counts separately from unique results. The source has 232 crossings, 44 kerbs, 38 entrances and 20 transit memberships. `node/10828764207` has two categories and receives one row and at most one marker. `node/8948926332` has two study-area memberships and likewise appears once. Key selections and map candidates by original node ID across category, way and section joins. Use a category-priority glyph with an additional-membership cue when needed and show every category in the accessible text and details. [Point-source handoff](https://github.com/oliverchennn/Curb/blob/e80f34b8fa3d0d2ba04a2954f97e94c4c06b0dd2/docs/research/CAMPUS_POINT_SOURCE.md)
- At whole-campus fit, show the results and the hint **Zoom in to see feature symbols, or browse the list**. Only the selected eligible position can appear at that scale. At close zoom, plot in-view eligible points at their original projected coordinates. Use distinct shapes that work on the Diagram and Aerial backgrounds. A crossbar, square, triangle and ring can distinguish crossing, kerb, entrance and transit. Give the selected symbol one halo. Reserve the existing section and way badge hit areas, then place independent 44 px hit areas at source positions where they fit. Prioritize the selection, then stable node order. Start with at most 24 interactive symbols in view and tune the zoom threshold in Chrome. When positions collide or fall against a plot edge, leave extras in the list and show how many matching positions are visible as symbols. A selected position can keep a non-interactive halo where its hit area would collide. Keep 22 section controls available at campus fit. Use the real plot bounds and screen scale already calculated by both map canvases. The geometry and coordinates stay fixed throughout.
- The feature browser shows a short page of results, with one selected record and its details. A symbol click and a list selection open the same record. **Show on map** centers the current campus view on the selected eligible position and can zoom to a readable scale. It keeps the current section selection, including for a point outside that section. Keep the atlas and tiles local and reuse the existing projection, aerial fallback and source credits.
- Label the 60 perimeter-context entries **Perimeter context · outside the selected campus boundary**. Label the 38 unlinked entries **No selected-way link**. Show actual joins where present and omit the coordinate-based audit grouping from the map and details. For `node/8776287626`, `node/11124620711`, `node/12785065968` and `node/12785065969`, show **Location review needed** with the source note. Those records remain selectable in search and details. Suppress normal map geometry and the **Show on map** action for them. Preserve original coordinates and tags in the ODbL data download.
- The detail view labels records as OpenStreetMap archive evidence and shows the node ID, source categories, relevant source tags, exact joins, source edit date and known retrieval lineage. Where part of the retrieval history is undated, state that beside the known dates. Show Observed, Capture and Current traversal as **Unknown**. Keep tag values as source assertions. Kerb and transit labels describe the source record without inferring a facility identity, building connection or route condition.

## URL and keyboard behavior

Keep the existing `group`, `collection`, `record`, `type`, `q` and `panel` meanings. Use separate point keys such as `features=1`, `node=<decimal ID>`, `featureKind`, `featureScope` and `featureQ`. Serialize filters deterministically and cap text to the existing 256-character search limit. A valid node link in campus opens the feature browser and selects that exact record, including unplaced and unlinked entries. For example, `?group=campus&node=10828764207` opens the crossing and kerb record. Honor an explicit campus section in a mixed link and leave its line record state available. Keep an explicitly selected record accessible if it falls outside the feature filter and identify that condition outside the result count. An invalid or missing node resolves to the normal campus state or the enabled inventory, depending on the explicit layer flag. An explicit legacy non-campus collection keeps its existing view. Switching away from campus or turning off the layer clears point state. Browser Back and refresh restore the encoded selection and filters using the existing history policy. Back to campus overview retains point settings and the campus picker focus behavior. **Reset demo** clears point state and restores the existing default.

Use an HTML result list with one roving tab stop per page. Up/Down and Home/End move focus. Enter or Space opens the record. All map-marker actions have a keyboard equivalent in this list, so keep the existing map tab order for section codes and way stops. Keep focus on search when results update and use a polite status for changes to the unique count. When keyboard interaction opens details, focus the detail heading. On close, return to the originating listed record or the browser button if it is no longer present. When the layer closes, return to the toggle. Keep pointer selection from shifting scroll. **Show on map** is explicit and can focus the map region when activated by keyboard. Respect the current reduced-motion rule for map movement, focus scrolling and disclosure changes.

## Interface and proposed implementation scope

The agreed interface keeps a separate inventory and an eligible geometry subset. At freeze, verify exact `node/<id>` lookup, stable unique inventory ordering independent of viewport, distinct category memberships and unique totals, exact section joins including empty lists, boundary and location-review flags, and the source note and date fields. Keep original coordinates available for export. The placement query uses `[west, south, east, north]` bounds with inclusive edges and documented invalid-input behavior. Both maps already measure screen scale and rendered bounds in projected space, so the overlay can clip and test hit areas with fixed source coordinates. The existing `Atlas` schema constrains `crossing` to a LineString and `ramp` to a Point. Consume the separately validated point catalog. [Approved interface](https://github.com/oliverchennn/Curb/issues/1#issuecomment-6888792408)

Proposed UI scope after assignment, all under `src/features/curb/explore/`:

| Literal path | Purpose |
| --- | --- |
| `Explorer.tsx`, `Explorer.module.css` | Optional layer state, controls, responsive rail and focus |
| `OverviewMap.tsx`, `MapCanvas.tsx`, `EvidenceStage.tsx` | Render the shared point overlay and pass selection and fit actions through the existing map views |
| New `CampusPointBrowser.tsx`, new `CampusPointMarkers.tsx` | Inventory, details and shared plot rendering and hit area rules |
| `location.ts`, `location.test.ts`, `campus.test.ts` | Point URL state, legacy URL regressions and focused visibility and target tests |

The catalog under `src/data/curb/princeton-campus-points/` is a dependency supplied by D. Reserve `app/curb/explore/campus-data/route.ts` separately for the integration owner so the public ODbL offer includes the exact rendered point source and its provenance alongside the existing line database, index and provenance. Download activation should remain an ordinary local link. The merge owner also handles any approved LF pin for the retained JSON. The three map components can reuse current SVG, projection and imagery. A mapping SDK, tiles from a new source and a runtime network service are unnecessary.
