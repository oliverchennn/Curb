The presentation assets sit alongside the existing normalized video and canonical survey anchors. The [frozen metadata interface](https://github.com/oliverchennn/Curb/issues/1#issuecomment-6892607055) gives the presenter UI a separate source frame, crop and seek time.

The [metadata](../../src/data/curb/surveys/robertson-presenter-frames.json) lists the crop rectangle, corresponding retained box, all ten asset hashes and the fingerprint of each finding track. Crop coordinates are integer source pixels from the upper left. For the per-finding SHA-256, serialize the track in ascending frame order. Each 36-byte record contains a little-endian unsigned 32-bit frame index followed by four little-endian float64 box values.

From repository root, use the existing FFmpeg executable. The published assets were prepared with FFmpeg 4.2.2 on Windows. The script uses Python's standard library and accepts an executable path when FFmpeg is outside `PATH`.

```text
python scripts/curb/prepare_presenter_frames.py --ffmpeg <ffmpeg>
python scripts/curb/prepare_presenter_frames.py --ffmpeg <ffmpeg> --check
```

The extraction checks the complete decoded timeline and then selects each frame by decoded index. Full stills use the original pixel dimensions. Crops preserve the pixel grid and use available surrounding context. The encoder converts the source color matrix for JPEG display. The check regenerates the outputs in memory and compares them with their checked-out bytes, normalizing line endings in the metadata JSON for Windows. Use the same FFmpeg encoder version for byte-level comparison.

## Verification

- The extraction and `--check` passed with FFmpeg 4.2.2. Both verified all 419 decoded timestamps against frame index ÷ 30. All ten JPEGs regenerated byte for byte and total 1,068,092 bytes.
- A read-only Node check independently serialized the five tracks with `DataView` and verified each fingerprint with Web Crypto. It verified all ten JPEG hashes and dimensions, enclosures of the selected boxes, the two source-video hashes and the canonical last-frame anchor.
- I inspected all five generated full-frame and crop pairs against the source and retained boundaries. The comparison sheets and command logs are private verification material.
- An independent read-only reviewer inspected all ten JPEGs, the five comparison sheets and the closer Defect 02 comparison. Separate Python checks confirmed frame keys, times, track spans and hashes, crop containment, JPEG dimensions and both source hashes. The reviewer found the selected evidence aligned and confirmed the right source-edge limit on Defect 04.
- The metadata JSON SHA-256 is `f2bfd306f9f9e9af3a3470e0e3538bbbeb8135f6161f60434143f22f90c8fd4a` with LF line endings. The older `npm run verify:media` verifier needs FFprobe, which was unavailable on this host. The checks above cover the new presenter-frame files.
